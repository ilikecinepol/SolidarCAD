# Официальный сайт SolidarCAD

Независимое статическое приложение React + TypeScript + Vite + React Router. Папка `website` не участвует в CMake и не меняет CAD-приложение. Требуется Node.js 22.12+ (проверено на 24.19) и npm.

```sh
cd website
npm install
npm run dev
npm run build
npm run lint
npm run preview
```

Результат сборки — `dist/`. Тестовый runner не настроен. Проверки браузера описаны в `VALIDATION.md`. `package-lock.json` фиксирует версии; для воспроизводимой установки можно использовать `npm ci`.

## Структура

- `src/pages/` — главная, download, docs, roadmap, about.
- `src/components/` — общий Layout, карточка релиза и демонстрационная область.
- `src/data/` — сведения о релизе, возможностях, roadmap и разделах документации.
- `src/styles/` — общие стили и цветовые токены.
- `src/App.tsx` — маршруты, заголовки страниц, canonical и обработка неизвестного адреса.
- `RESEARCH.md` — основания продуктовых утверждений.

Новые страницы добавляются отдельными компонентами и маршрутами. Документация использует `?topic=...`: ссылки можно сохранять и открывать напрямую. Статьи пока явно обозначены как готовящиеся.

## Как изменить текущую версию

Единственный источник — `src/data/release.ts`, объект `currentRelease`. До опубликованной сборки поля остаются пустыми; интерфейс не генерирует номер версии, дату, размер или SHA-256. Ссылка загрузки активируется, когда указаны `version` и `downloadUrl`.

Интерфейс `Release` отделяет представление от источника данных: позже GitHub API может возвращать такой же объект. Сейчас сетевых запросов к GitHub из приложения нет.

## Как опубликовать новую версию MVP

1. Подготовить и проверить Windows x64 архив/установщик со всеми runtime-зависимостями.
2. Создать GitHub Release в репозитории SolidarCAD, прикрепить сборку и release notes. Сайт не хранит дистрибутивы.
3. Вычислить хэш именно загружаемого файла: `Get-FileHash <file> -Algorithm SHA256`.
4. В `currentRelease` заполнить version, channel, platform, downloadUrl (прямая ссылка на asset), releaseUrl, releaseDate (YYYY-MM-DD), size, sha256 и notes.
5. После проверки дистрибутива уточнить системные требования в `DownloadPage.tsx`.
6. Выполнить install/build/lint, проверить скачивание, размер и хэш. Опубликовать новый `dist/` на выбранном статическом хостинге.

Создание CAD-релиза, push и публикация сайта в рамках этой задачи не выполняются.

## Как заменить screenshot

Добавить реальный снимок приложения в `public/screenshots/interface.png` и пересобрать сайт. Layout и компоненты менять не нужно. Пока файла нет, Vite обнаруживает его отсутствие при сборке и отображает placeholder без 404-запроса. При повреждённом изображении также работает fallback.

Используется официальный ресурс `src/assets/solidarity-3d-logo.png` основного проекта (копия в `public/logo.png`); в header видна эмблема этого ресурса. Новая эмблема не создавалась. Референсы интерфейса не выдаются за screenshots продукта.

## Статический хостинг и отдельный домен

Сайт подготовлен для корня отдельного домена. Настройте fallback всех маршрутов приложения на `index.html` с HTTP 200, сохранив обычную выдачу существующих assets. Например, для nginx: `try_files $uri $uri/ /index.html;`. Без fallback прямое открытие `/docs` или обновление страницы может дать 404. GitHub Pages без собственного SPA fallback для этой конфигурации не подходит.

Перед production-сборкой скопируйте `.env.example` в `.env.local` и укажите `VITE_SITE_URL=https://ваш-домен`. Это публичный origin, не секрет. Canonical формируется для маршрута без query-параметров. Пока домен не определён, canonical намеренно не добавляется. Базовые OpenGraph и description включены; preview-картинка не выдумана. Для индексации всех страниц и отдельных OG-карточек без выполнения JavaScript впоследствии можно добавить prerendering.

Аналитика, telemetry, backend, авторизация и облачные API отсутствуют. Сайт не загружает сторонние шрифты.
