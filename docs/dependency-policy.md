# Политика сторонних зависимостей

## Обязательное правило

Новая сторонняя библиотека не включается в main до прохождения Dependency
Gate. Запрещено делать базовый CAD-функционал зависимым от закрытого
иностранного SDK, обязательного зарубежного SaaS, license server или cloud API
без отдельного письменного архитектурного и юридического решения.

## Dependency Gate

Автор изменения до merge обязан:

1. Обосновать функциональную необходимость и проверить существующие средства.
2. Зафиксировать точную версию или воспроизводимый commit/baseline.
3. Проверить лицензию, коммерческое распространение и способ линковки.
4. Описать runtime-поведение, внешний контроль и возможность offline-работы.
5. Оценить возможность сборки и эксплуатации без зарубежной инфраструктуры.
6. Определить заменяемую границу/адаптер для критической зависимости.
7. Обновить `DEPENDENCIES.md`, `THIRD_PARTY_NOTICES.md` и `LICENSES/`.
8. Обновить SPDX SBOM и автотест compliance-артефактов.
9. Назначить владельца зависимости и план обновления/устранения уязвимостей.

## Допустимые лицензии

Предпочтительны MIT, BSD и Apache-2.0. LGPL допустима после проверки способа
связывания и комплекта обязательных материалов. GPL-компоненты нельзя линковать
с закрытым кодом без отдельного решения. Лицензия собственного кода проекта
выбирается независимо.

## Release Gate

Перед каждым релизом список сравнивается с фактическим staging-каталогом.
Релиз блокируется при неизвестной runtime-библиотеке, отсутствующей лицензии,
несогласованной версии или обязательной внешней SaaS-зависимости.
