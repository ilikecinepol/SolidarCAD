# Задача для Codex — контур реестровой готовности 0

Дата: 28 августа 2026 г.

## Контекст

По дорожной карте на 27–31 августа 2026 года проект должен получить минимальный
контур учёта сторонних компонентов. Эта работа выполняется параллельно с CAD-
функционалом и не должна менять поведение Sketch, Extrude, Pocket или Fillet.

## Цель

Сделать состав продукта проверяемым: зафиксировать прямые зависимости, их
версии, назначение, лицензии и способ связи; определить dependency gate;
добавить notices, каталог лицензий и базовый машинно-читаемый SBOM.

## Объём работ

1. Создать `DEPENDENCIES.md` как единый реестр прямых runtime/build-зависимостей.
2. Создать `THIRD_PARTY_NOTICES.md` с атрибуциями Qt и OCCT.
3. Создать `LICENSES/` с инструкцией по комплектованию релиза и карточками
   прямых компонентов.
4. Создать `docs/dependency-policy.md` с обязательной проверкой новых библиотек.
5. Добавить базовый SPDX 2.3 SBOM в `sbom/solidarcad.spdx.json` и описать его
   обновление.
6. Исправить устаревшее утверждение о предполагаемой лицензии в README.
7. Добавить CTest-проверку обязательных артефактов, валидности JSON и
   согласованности версии OCCT с manifest.

## Ограничения

- Не добавлять сторонние библиотеки и сетевые runtime-сервисы.
- Не менять CAD-модель, UI и текущие незавершённые изменения Fillet.
- Не объявлять лицензию собственного кода до решения правообладателя.
- Не заявлять, что каталог содержит полный комплект транзитивных лицензий:
  это формируется из фактического release-пакета.

## Критерии приёмки

- Все перечисленные артефакты существуют и содержат обязательные поля.
- SBOM является корректным JSON и указывает SPDX 2.3.
- OCCT привязан к baseline из `vcpkg.json`; фактическая локальная версия 8.0.1
  отмечена как проверенная для текущего окружения.
- Qt 6.11.1 отмечен как версия текущего локального профиля, при этом минимальная
  версия сборки 6.5 остаётся взятой из CMake.
- Автотест compliance-артефактов проходит через CTest.
- Существующие автотесты проекта по возможности проходят без регрессий.

## Итоговый отчёт

Указать созданные файлы, зафиксированные версии, результат нового и полного
набора тестов, сознательные ограничения и следующий шаг: генерация SBOM и
копирование точных license texts из фактического release staging в CI.

## Дополнение: стабилизация и Model Ribbon

После compliance-этапа выполнить связанную стабилизацию текущего рабочего
дерева:

1. Устранить зависание `project_file_tests` и сохранить диагностируемый отказ.
2. Перенести «Скругление» (Fillet) из «Расширенных» в «Редактирование».
3. Удалить из ленты отдельные кнопки стандартных видов Top, Front, Right и
   аналогичные: ориентация уже доступна через куб 3D-вида.
4. Для каждой группы Model Ribbon («Создание», «Редактирование», «Вид»)
   добавить выпадающий список её инструментов по образцу Sketcher.
5. Покрыть структуру ленты автотестом и прогнать полный CTest.
